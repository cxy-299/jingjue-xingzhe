# M1 编码器串口精细标定（EMR3）

此版本仅供**四轮离地**的单轮开环标定，不是 PID 闭环位流，也不能让车辆落地行驶。M1 对应左后/B 轮；M2～M4 的 PWM、IN1、IN2 全部恒低。S1 单击后，M1 用 100 ms 全占空比起动，随后 80% PWM，到 700 ms 硬超时自动停止。S0 可以立即停车并复位计数、串口。

## 读数与接口

- FPGA 用编码器四倍频位置，取起动后 200～700 ms 的 500 ms 窗口，计算该段平均每 10 ms 的计数绝对值并保留整数部分。负号是**编码器原始极性**；M1 车体前进方向负号已由 EMD1 上板确认。
- 停机并计算完成后，FPGA 板载 USB 串口 TX（M15）只发送一行 ASCII，例如 `M1:-026\r\n`。串口为 **115200，8N1**。该值表示 26 个四倍频计数/10 ms，不是 RPM；要换算 RPM 尚需轮轴每圈四倍频计数。
- 若平均读数超过 999，输出 `M1:!999\r\n` 表示溢出，不能作为精确读数。若显示 `M1:-000`，也不能据此认定编码器故障，应先区分极慢转速与接线问题。
- LED2 心跳、LED3 就绪、LED4 运行、LED5 硬超时、LED6 计算完成、LED7 溢出。与 EMR1 停机后复用 LED2～7 为六位数值**不同**，不要混用解读。
- 若由树莓派读取，USB 串口线保持接 Pi；读取时必须由一个串口进程独占读端。若 GUI 服务正在占用串口，先安全停止**该服务**后再使用终端读取，之后再启动服务；不重启树莓派或电脑。此步骤待上板时核对，不应假设已有串口实测。
- 当前优先完成比赛基础任务 1～3，用户选择先由电脑直接读取。关闭驱动板 12 V 后，可将原先接在树莓派 USB-A 的 FPGA 板载串口 Type-C 线改接电脑，使用新出现的 CH340 串口端口接收；**FTDI 下载器的 COM4 不是该串口**。电脑串口接收设置仍为 115200、8N1。勿同时让 Pi 与电脑占用同一串口，也勿把独立 USB-TTL 模块的 5 V VCC 接至 FPGA GPIO。

## 离线验证（2026-10-23）

- ModelSim 2020.4：`PASS tb_acg720_motor_encoder_uart: M1 hard timeout, UART frame M1:-010, reset`，编译与仿真 0 errors、0 warnings。覆盖了仅 M1 动作、700 ms 超时、9 字节 8N1 格式、负极性与 S0 复位。
- Gowin V1.9.12.04：GW5AT-60B，50 MHz 约束下 Actual Fmax **99.662 MHz**，建立/保持违例终点均为 0。引脚报告确认 TX 在 M15；数码管扫描逻辑因输出未使用而被移除，不再占用有冲突的 M18。
- 文件：`impl/pnr/acg720_motor_encoder_uart.fs`；User Code `0x454D5233`（EMR3）；SHA-256 `1ABACA73C2BF307D266F01AE4FE880307EB24FFE0861AD13D259C96101EEBA96`。
- 用户确认驱动板 12 V 已关闭、四轮离地；已于 2026-10-23 只执行 SRAM Program（未写 Flash）。Gowin 返回 `Finished`、User Code `0x454D5233`、Status Code `0x70026020`。用户确认下载后保持 12 V 关闭、S1 松开时，LED2 规律闪烁、LED3 常亮、LED4～7 全灭，四轮静止。
- 上板试转仅 M1 转动并自动停止；LED5、LED6 亮，LED4、LED7 灭。电脑 XCOM V2.6 在 COM6、115200、8N1 收到三次独立实测 `M1:-026`、`M1:-027`、`M1:-027`。因此 M1 空载 80% 附近约为 26～27 个四倍频计数/10 ms，且原始前进方向为负。尚未测轮轴每圈计数，也未测试负载闭环。

## 未完成的闭环验证

当前唯一硬件速度观测来自 EMR1：80% 空载 M1 的读数区间为 26～28 个四倍频计数/10 ms。EMR3 将给出更精确整数及符号，但仍未建立 M1 每圈计数、带载变化、转速目标、起动最小占空比和 PI 参数。闭环必须先在 FPGA 内将 M1 负极性转换为车体正向反馈，再做限时单轮 PID/PI 仿真及上板；完成这些之前不得宣称四轮闭环已验证。
