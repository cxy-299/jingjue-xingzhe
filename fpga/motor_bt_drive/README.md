# 蓝牙四向闭环离地试验（BTD5）

当前 SIN4 集成位流、IMU/ToF GUI 回传、ToF 急停锁停、逐轮 PI 故障定位与减速闭环的构建、仿真及 SRAM 下载记录见 [SIN4 维护记录](../../output/board/SIN4_PI_TOF_DIAGNOSTIC_2026-10-26.md)。[SIN3 维护记录](../../output/board/SIN3_TOF_STOP_INTERLOCK_2026-10-25.md)及下文保留早期阶段性结果，不能替代 SIN4 的实机验收。

本工程仅用于四轮**离地**验证蓝牙前、后、左、右控制，不能直接作为落地行驶或比赛正式位流。实物车头按用户确认的 **M1/M2 端**，M3/M4 为车尾。四路速度 PI 来自已经离地实测的 4CL2；BTD4 增加 S0 复位后的显式停止锁，BTD5 增加蓝牙侧编码器诊断回传。

## 硬件接线门槛

驱动板 12 V 先关闭，FPGA 和蓝牙模块断电后才接线。ZS-040 底板六针丝印（背面排针朝下从左到右）为 `EN、VCC、GND、TXD、RXD、STATE`；底板名称不代表某个确定的供电规格。先确认所持模块允许的 VCC 输入，再给模块单独上电并以模块 GND 为参考实测 TXD 空闲高电平；**确认不超过 3.3 V 后**，才能将 TXD 接 FPGA P7-23/E16。FPGA 与蓝牙模块须共地，5 V 绝不能直接送入 FPGA GPIO。

先下载 [蓝牙隔离回显位流](../bluetooth_bringup/README.md) 验收 9600/8N1、TXD/RXD 与回显；该位流所有电机输出固定为低。2026-10-24 已用 Windows 蓝牙 SPP COM9 发送 `A`、`B`、`A` 并收到完全对应的回显，证明电脑—蓝牙—FPGA 双向串口贯通，**未验证电机遥控**。当前 iPhone 小程序不支持这只经典蓝牙模块，可先使用 Windows。

## 手机蓝牙助手协议

Windows 可使用 [pc_bt_control.py](pc_bt_control.py) 进行离地遥控（`python pc_bt_control.py --port COM9`，需 `pyserial`）。点击连接发送停止 `S` 和标准速度档 `3`；还须手工勾选“允许离地试转”。方向按钮必须按住才会每 100 ms 重发，松开、窗口失焦或关闭时发 `S`。换向先停，必须松开后重新按目标方向。**BTD4 不要求按 FPGA S1**，但仍保留 S0 急停、FPGA 失联看门狗和驱动板电源开关。方向字节持续刷新时，点击锁定可以连续运行；最后一个刷新字节之后约 300 ms 无刷新，FPGA 自动停车。XCOM 不得同时占用 COM9；诊断仍走板载 COM6/115200。

手机按钮按下时每 100 ms 重发一个 ASCII 字符；松开时发一次 `S`。仅发送单个字节、不重复的按钮最多运行约 300 ms。`\r`、`\n` 和其他字符不刷新安全看门狗。

| 按钮 | 发字符 | 轮速方向（+ 表示该轮朝车前进方向） |
|---|---|---|
| 前 | `F` | M1+、M2+、M3+、M4+ |
| 后 | `B` | M1−、M2−、M3−、M4− |
| 左横移 | `L` | M1+、M2−、M3−、M4+ |
| 右横移 | `R` | M1−、M2+、M3+、M4− |
| 停止 | `S` | 全部 PWM、IN1、IN2 为低 |

`L/R` 使用标准麦克纳姆 X 布局组合；底盘滚轮的实际 X/O 安装、左右运动方向尚未落地验证。若实车安装不同，必须根据低速地面测试修正，不能凭离地轮转断言横移正确。

速度档位仅在停车时生效：`1`、`2`、`3` 分别设置闭环目标 **12、16、20 个编码器四倍频计数/10 ms**；运动中收到调速字节会忽略。电脑界面调档先发 `S` 再发档位字节。默认档位为 `3`；这些是计数目标，不是已校准的 m/s。最高档不超过此前四轮离地实测的 20，最低档能否稳定维持仍待实测。板载串口诊断中的 `Txxx` 随档位显示实际目标。

## GUI 死手控制与 FPGA 停机

1. 上电就绪后至少保持 100 ms 中性状态。GUI 的本地“允许离地试转”默认关闭；只有按住方向按钮才每 100 ms 重发 F/B/L/R，松开即发 `S`。FPGA 不依赖 S1。
2. 最后一个合法方向字节之后约 300 ms 无刷新即全停；同方向刷新会清零运行租约计时，不再因固定 3 秒计时器误停。换向仍须先发送 `S` 并等待约 100 ms 中性间隔，再发送新方向。
3. 从运动中直接换向立即停车并锁定；先发送 `S` 再发新方向。S0 急停直接门控全部输出；**S0 松开后仍锁停，持续刷新的旧方向字节无效，必须先收到 `S` 才能重新起动**。串口帧错误、任一编码器无反馈、反向反馈或超速也导致全停。若 GUI 已连接而 FPGA 后复位，先松开方向并点一次“停止 S”。
4. 四轮错峰起动由 BTD2 的每路 125 ms 缩为 **40 ms**（M4 最晚 120 ms），仍有 100 ms 起动脉冲。此前 0.5 秒 BTD2 试验中 M3/M4 几乎不转，最晚启动 375 ms 是重要解释，但尚不能排除机械阻力、供电或 PI 参数因素。PI 占空比限幅 300～850‰；只有离地验证后才能讨论落地调参。

板载 CH340 串口仍以 115200/8N1 轮询发送 `M1 T020 A+020 D0700 F0` 之类诊断帧；BTD5 还从 D16/P7-24 以 9600/8N1 向蓝牙模块回传同类 M1～M4 诊断帧，GUI 可在 COM9 显示最新行。LED2 心跳、LED3 就绪、LED4 任一路输出、LED5 蓝牙/连续运行超时、LED6 四路都曾收到反馈、LED7 安全告警。
