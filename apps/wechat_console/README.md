# 境觉行者 · 微信小程序驾驶台

这是原生微信小程序工程，配套电脑中转网关。保留现有接线：手机 → 同一 Wi‑Fi 下的电脑 → 原蓝牙串口 → FPGA；树莓派仍通过原 USB 串口向 FPGA 发送视觉状态。

## 先体验，不需要 AppID

1. 在微信开发者工具中导入本目录 `apps/wechat_console`，项目配置已指向 `miniprogram/`。无 AppID 时选择工具允许的测试/游客项目模式；`touristappid` 是占位配置。
2. 编译后默认进入**离线演示**，不需要电脑网关、树莓派、串口或机器人。
3. 点击“启用本次控制”，在“驾驶”页按住方向键，松手停止；“地图”页点击空闲格预览，启动模拟导航；“视觉”页可以模拟选择数字、准备任务和跟随。
4. 任意页面底部“停止 S”取消运动及任务。切到后台、返回前台后均需重新明确启用。

不安装开发者工具也可以双击 `qa/preview.html` 查看并操作浏览器演示。该文件由同一套 WXML/WXSS 生成，供布局和交互预览，**不是微信运行时**，只提供离线数据。

## 四个页面

- **驾驶**：ToF 距离、IMU 航向、按住式前后/横移、三个速度档、90°转向、普通前进避障开关、四轮目标/反馈/PWM。
- **地图**：实际地图 0x2613 的20×20格预览、选终点、停车确认位置、探头偏移配置、启动板内规划；测点来自电脑现有的新鲜回传判断。
- **视觉**：相机快照、0–9数字选择、当前具体目标点选确认、准备/读取/启动智能任务、ToF20cm跟随及数字触发跟随。
- **连接**：离线演示切换、电脑地址与本次配对码、控制链路、停车 PID 配置及最近操作。

## 已完成实机验证与电脑中转准备

微信小程序已经完成实机连接与控制验证，手机经电脑中转接入原蓝牙—FPGA控制链路。此状态依据项目作者的现场实测确认。操作前使用配套驾驶台入口，保持停车完成本次许可检查；旧驾驶台与新网关不能同时占用同一蓝牙COM口。

电脑需 Windows、Python3.10及以上（包含 Tkinter）和原蓝牙串口。只需额外安装 pyserial：

```powershell
python -m pip install -r apps/wechat_console/requirements-gateway.txt
python apps/wechat_console/start_pc_gateway.py --port COM9 --pi-base http://192.168.137.129:8080
```

请在项目根目录运行。COM9 和树莓派地址是现有环境示例，可按现场修改。启动器默认不自动连接蓝牙。它打开原驾驶台，并添加“微信小程序局域网网关”区域，显示电脑地址和每次进程随机生成的配对码。

在电脑完成原有固件核对、传感器检查、几何/地图确认及本次运动许可；再勾选新增的“允许本次手机控制”。手机不能修改这些电脑侧确认。首版真实入口限定新鲜 K14/R20 能力回传。

手机与电脑在同一受信任 Wi‑Fi，选择电脑实际局域网 IPv4 地址。手机不能使用 `127.0.0.1` 连接电脑。若 Windows 防火墙询问，按现场网络策略仅允许所需的专用网络；本程序不会自动修改防火墙。

小程序“连接”页关闭离线演示，填写 `http://电脑IP:8765` 与配对码，连接后再点击“启用本次控制”。电脑侧许可不足时，网关会说明缺少的条件，连接本身不会授予运动权限。

## 真实任务操作

**手动驾驶**：在电脑明确许可后，手机启用本次控制，再按住方向键。松手或触摸取消会发送停止，并清除排队的旧按压指令。速度切换、转角、避障开关仍调用原驾驶台操作，原有板端回传与停车门继续生效。

**板内规划**：先停车确认实际位置与 +Y 车头方向，点击空闲格设置终点。电脑仍需勾选原地图/导航及车体几何确认，手机启用后启动。小程序蓝线是参考预览，不替换 FPGA 规划；真实占用和近障停车处理沿用现有固件。

**智能接近**：选择数字与到达距离，准备新任务；待视觉状态确认后读取任务，再重新启用手机控制并启动。参数准备与读取都会先撤销旧运动，防止带着旧任务继续行驶。原驾驶台还会在启动时重新核验 Pi 意图和板端条件。

**数字触发跟随**：在“当前识别目标”中点选当前可见的具体目标，等待 Pi 与 FPGA 确认，再启用“数字确认后跟随”。数字只触发一次，后续是原驾驶台的 ToF20cm跟随；这不替换为持续视觉对准。可直接使用“ToF 跟随20cm”。停止 S 均取消。

## AppID与部署配置

手机与实物机器人连接、控制已经实测可用。仓库的`project.config.json`仍使用`touristappid`通用占位，便于源码分享；导入微信开发者工具时配置自己的AppID，本机私有配置不提交。项目的已验证运行方式为局域网电脑中转，正式发布时按微信平台要求配置域名与隐私信息。已完成实机使用不等同于声称已通过平台审核或上架。

## 许可与停止机制

网关不打开第二个串口，HTTP线程也不直接操作 Tk/串口。请求进入有截止时间的队列，最终在原 Tk 主线程调用白名单操作。每次连接创建新会话，命令有递增序号与绝对过期时间；旧会话、重复序号和超时指令拒绝执行。

额外手机租约为400ms，前台每100ms续期；原 FPGA 的普通/智能许可时限未修改。网关自身运行时定期检查手机租约和电脑许可。进入后台、断线、电脑停止/撤销许可、网关退出会停止；重新进入前台不自动恢复。手机停止请求属于网络尽力发送，网络或进程阻塞时仍依靠网关租约和原板端失联保护，不能理解为操作系统级硬实时保证。

配对码为每次进程随机值，手机只在内存保存。HTTP不加密，因此仅适合受信任的专用局域网，不能将网关端口直接映射到公网。手机不提供固件下载、故障强制解除、电脑侧运动许可修改或任意串口写入接口。

## 仅测试网络链路，不连接硬件

```powershell
# 项目根目录运行；此入口只加载模拟后端
cd apps/wechat_console
python -m gateway.server --host 127.0.0.1 --port 8765
```

模拟网关仅输出地址及本次配对码。开发工具与模拟网关同机时可用127.0.0.1；实体手机需要电脑实际地址，并显式把模拟网关绑定到所需局域网地址。关闭模拟网关使用 Ctrl+C。

测试入口、实际结果和验证范围见 `docs/VALIDATION.md`。传输协议和文件结构见 `docs/ARCHITECTURE.md`。
